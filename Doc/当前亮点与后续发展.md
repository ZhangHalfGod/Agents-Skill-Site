## 一、当前已建成亮点

### 1.1 完整的 Agent 角色流水线

| 阶段 | 角色 | 输入 → 输出 |
|:----:|------|-------------|
| 需求 | ProductManager | 原始需求 → 《AI代码生成范围清单》 |
| 设计 | Architect + UIDesigner | 需求 → 架构约束 + 接口数据模型 |
| 开发 | DevLead | 设计 → AI Prompt + 代码产出 + CR 记录 |
| 测试 | TestEngineer | 代码 → 《AI代码测试报告》 |
| 安全 | SecurityEngineer | 代码 → 《AI代码安全报告》 |
| 上线 | OpsEngineer | 测试通过 → 部署 + 版本映射 |

- 每个角色有独立的 Skill 和交付物标准
- 不是"AI 干所有事"，而是**业务流程驱动 AI 分工**

### 1.2 模型分层调度

| 角色/场景 | 模型层级 | 原则 |
|-----------|----------|------|
| 架构师 / PM（市场调研、可行性、架构设计） | 顶级模型 | 核心决策须高推理能力 |
| 开发者 / 设计师 / 测试 / 运维 | 中等模型 | 执行效率优先 |
| 文档类工作 | 高性价比模型（如 DeepSeek） | 成本优先 |

> 按 ROI 分配模型资源，不是无脑上最强模型。

### 1.3 MCP 总线架构

```
对话入口（extern-api）
    │
    ┌─── MCP ───┐
    │            │
mcp-gaode    mcp-faq
（出行工具）  （机械 FAQ）
```

- 自建 MCP HTTP 服务（`GET /capabilities` + `POST /tools/call`）
- 全局工具注册表（`travelToolRegistry.js`）
- 严格**只读发现**，MCP 不沾写操作

### 1.4 知识循环系统（记忆层）

```
MCP list/get → @ source 正文 → 干活 → 出门清单
    → 写 Lesson raw → 蒸馏合进 skill
    → generate + validate → commit + push
    → 服务器 pull + build
```

- Lesson 状态机：**raw → distilled → merged → rejected**
- MCP 严格只读，蒸馏经人工判断
- 不是对话级记忆，是**项目级 + 技能级持久记忆**

### 1.5 OpenClaw 双 Bot 协调

| Bot | 角色 | 模型 | 用途 |
|-----|------|------|------|
| **bm** | 验证机 | 云端 qwen3.7-max | 飞书试验床、云端能力验证 |
| **Home** | 家里主机 | 本地自部署 + TTS/Tailscale | 个人助手、定时简报、本地服务 |

- 两 Bot 可并行，凭证隔离
- 定时简报 Cron 体系（四类场景）
- 模型配置面板（Open-OpenClawModelPanel）

- 类似 "部署验收证据分层" 的教训 → 自动推送到所有项目的 stage-gate skill
- 减少每个项目重复踩坑

>
> **闭环首跑（2026-07-29）**：首批 3 张 raw 卡人工终审完成——2 merged（新公共 skill `openclaw-ops` / `powershell-utf8`，skills 11→13）、1 rejected（半条抢救进路由表 §6.1）；周推 → 终审 → 公共库全链路实战验证，建议清单归零。

### 优先级 ②：用 OpenClaw 做 Agent 编排总线

> Agent 间不再靠手动 @ 来 @ 去，而是自动流转。

```
用户需求 → OpenClaw Gateway
  → ProductManager Agent（顶级模型）
    → session 传给 Architect Agent
      → 传给 DevLead Agent
        → 通过 MCP 调 extern-api / mcp-gaode 干活
          → 产出 → Manifest → commit → 部署
            → Lesson 蒸馏回灌 skill 库
```

- OpenClaw session routing 天然是 Agent 通信协议
- 现有 MCP 服务直接注册为 OpenClaw tool
- 不需要自研 Agent-to-Agent 协议

> **状态（2026-07-29，四期 4B 进行中）**：交接契约 / 路由表 / 工具注册映射已进 `Doc/phase4/`，配置样例进 `Code/orchestration/`；**最小两跳试点已跑通**（PM → Architect，`deepseek/deepseek-v4-flash`，证据 `Code/doc/phase4/pilot/`）；**机制 A 已验证**：bm 建齐 pm/arch/ui/dev/test/sec/ops 七个命名 agent（统一 flash，SOUL.md persona，auth 逐 agent 隔离），Cron 定案（`Doc/phase4/03` §6）；**weekly-lesson-digest 已上线 bm**（cron agent 消息任务，周一 09:00 推飞书简报群，`Code/orchestration/cron/`，08-03 首跑）。剩余：H3 起全链路推广、信封 schema 机器校验。

## 四、关键认知

### 4.1 当前定位

介于"个人工具"和"企业产品"之间。后续最有价值的动作不是加功能，而是**选一个口子走深走透**。

### 4.2 与宏观周期的关系

- 房地产/旧经济周期下行，但 AI 技术革命正在接棒
- 核心不是 AI 是否成为 AGI，而是 AI 能否像互联网一样**在商用化的路上持续释放红利**
- 这套基础设施瞄准的正是「AI 商用落地」这个历史窗口

### 4.3 核心竞争力

不是工具本身，而是**系统设计思维**——把 AI 当成基础设施来设计，不是当成工具来用。Agent 编排协议、模型分层调度、多机 MCP 总线、知识循环系统，这些是团队级/企业级 AI 落地的架构范本。
