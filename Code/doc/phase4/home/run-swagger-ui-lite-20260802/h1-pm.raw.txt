## 1. 目标

新增 `GET /api/docs/ui` 路由，返回轻量 HTML 页面，加载 `/api/openapi.json` 并按路径分组渲染 API 列表。不改业务 API、不装新依赖、不触 CSP 拦截。

| 不改业务 | 现有 `/api/*` 与 openapiGenerator 不变 |
| 零依赖 + CSP 兼容 | 无 npm install；inline script/style 已在 `'unsafe-inline'` 白名单 |

---

## 2. 范围条目

### 2.1 原位探查

| 检查项 | 结论 |
|--------|------|
| `openapiGenerator.js` | **无 tags**（openapi.json 仅有 paths，无 tags 分组） |
| `node_modules/swagger-ui-dist` | **不存在**（CDN 是唯一引入 swagger-ui 的途径） |
| CSP（server/index.js L80） | `scriptSrc/styleSrc: 'self' + 'unsafe-inline'`，**无 CDN 域**——CDN swagger-ui 需放宽 CSP |
| `/api/docs` vs `/api/docs/ui` | 路径不冲突（`/api/docs` 在 chatRoutes，`/api/docs/ui` 在 openapiRoutes） |
| 路由挂载 | `app.use('/api', apiLimiter, openapiRoutes)` → 新路由自动继承限流 |

### 2.2 方案对比（提交 H2）

| 方案 | 优势 | 劣势 | 建议 |
|------|------|------|------|
| **A：自研极简 HTML** | 零依赖、CSP 无需改、离线可用 | 非标准 swagger-ui 外观 | **P0** |
| B：CDN swagger-ui-dist | 完整 Swagger UI | 需改 CSP（加 CDN 域）、外部依赖 | P2 |

### 2.3 修改条目（P0 — 方案 A）

| # | 文件 | 动作 |
|---|------|------|
| M1 | `server/routes/openapiRoutes.js` | 新增 `router.get('/docs/ui', (req,res) => res.type('html').send(HTML_TEMPLATE))` |
| M2 | 同上 HTML 内容 | 自研 ~130 行：fetch `/api/openapi.json` → 按路径第二段分组 → `<table>` 含方法徽章（GET=绿 POST=蓝 DELETE=红）+ 路径 + 摘要 |

### 2.4 分组映射

| 路径前缀 | 显示名 |
|---------|--------|
| `/api/auth/*` | 认证 |
| `/api/chat/*` | 对话 |
| `/api/faq/*` | FAQ |
| `/api/repair-records/*` | 维修 |
| `/api/admin/*` | 管理 |
| `/api/system/*`, `/health` | 系统 |

### 2.5 不修改

openapiGenerator.js（不改加 tags）、server/index.js CSP、现有业务路由、npm install、git push
