### 摘要

**模块拓扑**: LAYERS（registry.js）为真源 → `collectLayerEndpoints()` → `generateOpenApiSpec()` / `getApiDocsPayload()` / `v2Catalog`。voice 进 chat 层后，`byPath.get()` 命中 LAYERS，`PATH_FALLBACKS` 分支不被触发。

**改点精确约束**:
- **A1** — `registry.js` LAYERS chat 层新增 voice 模块（3 端点, auth:true, implemented:true），parameters 对齐真实 handler: `{ text, conversationId, messageId, save }`（非过时的 voice/speed）
- **A2** — `getApiDocsPayload()` 顶层加 `openapi: { json, yaml }`，向后兼容
- **A3** — system/docs 加 openapi 端点，**降为 P1 可选**（A2 已满足验收①）
- **M1-M3** — `PATH_FALLBACKS` 仅去 xNote，其余字段不动
- **M4** — voice fallback 保留为安全网，不删，不改 xRegistryStatus
- **M5** — 测试断言翻转：`x-registry-status` → `undefined`，新增 `security` + `responses.401` + `required.text` 检查
- **M6** — 快照更新

**三条 open_questions 裁决**:
1. PATH_FALLBACKS voice 键 → **保留**（安全网，控制流走不到）
2. A3 是否必须 → **非必须**（A2 已满足验收①），建议 P1
3. VOICE_TTS parameters → **对齐 handler**：`{ text, conversationId, messageId, save }`

**隐式依赖**: 全部通过 — auth:true 副效应对齐，x-generator 保持，无 router/middleware 隐含逻辑，改动面 ⊆ 白名单文件。
