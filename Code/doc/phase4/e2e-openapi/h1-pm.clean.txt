## 1. 目标

为 extern-api 生成标准 **OpenAPI 3.0.3** 规范文档，通过新增只读端点 `GET /api/openapi.json` 暴露，供 Swagger UI 渲染与 CI 契约校验使用。生成器以现有 `server/catalog/registry.js`（`LAYERS` + `API_PATHS`）为单源真源，不引入第二套描述体系。

**业务指标**：
- 一次 `GET /api/openapi.json` 即可拿到合法 OpenAPI 3.0.3 JSON，可被 swagger-parser / openapi-generator 等工具直接消费
- `npm run test:server` 全部通过（新增 + 存量）

## 6. 核心模块AI生成红色记录

| 字段 | 内容 |
|------|------|
| **模块名** | `server/catalog/openapiGenerator.js` |
| **变更范围** | 新建文件，~150 行，纯函数从 LAYERS + API_PATHS 生成 OpenAPI 3.0.3 对象 |
| **风险点** | 1) 路径参数化错误（如 `:id` 路径在 OpenAPI 中需转为 `{id}`）；2) API_PATHS 与 LAYERS 不一致时补全策略失当；3) 快照漂移——registry 增删端点后快照测试需同步更新 |
| **审查人** | Architect（H2 跳） |
| **审查结论** | 待 H2 架构审查 |
| **关联 Prompt 版本** | H1 scope-list（本清单） |
| **缓解措施** | 1) 生成器统一 `:param` → `{param}` 转换；2) 对 LAYERS 未注册路径使用保守推断（method=GET, auth=false, no parameters），不造假设数据；3) 快照测试失败时提示「请更新快照文件」 |

## 7. 风险与依赖

| 风险/依赖 | 影响 | 缓解 |
|----------|------|------|
| `API_PATHS` 与 `LAYERS` 存在 7 条路径缺口（voice×3, gateway×3, V2_ROOT） | OpenAPI 生成器需自行补全这些路径的元数据，可能不准确 | 见 §6 缓解措施；缺口路径标记 `x-registry-status: "inferred"`，供 H2 审查 |
| 路径参数转换（Express `:param` → OpenAPI `{param}`） | 转换遗漏会导致路径不匹配 | 测试逐条校验所有带参数路径 |
| 快照测试在 registry 变更后失效 | 新增端点会导致快照不匹配，测试变红 | 快照失败信息包含「请更新快照」指引 |
